## 1. Постановка задачі та математична модель

ДПС приводить жорстко з'єднане інерційне навантаження. Потрібно досягти заданої швидкості протягом 2 с, зменшити похибку та керуючий вплив, зіставити різні реалізації моделі й перевірити компенсацію моменту навантаження.

{{table:parameters}}

Сумарний момент інерції J = Jm + JL = 0.03 кг·м². Навантаження додає лише інерцію; додаткове тертя не задано. Додатний момент TL протидіє додатному обертанню. Початкові умови задаються окремо для кожного сценарію.

La·di/dt = Vin - Ra·i - Ke·ω

J·dω/dt = Kt·i - Bm·ω - TL

За нульових початкових умов та TL = 0:

G(s) = ω(s)/Vin(s) = 0.1 / (0.015·s² + 0.0605·s + 0.012)

Gd(s) = ω(s)/TL(s) = -(0.5·s + 2) / (0.015·s² + 0.0605·s + 0.012)

Вектор станів x = [i; ω]. A = [-4, -0.2; 10/3, -1/30], Bu = [2; 0], Bd = [0; -100/3]. Виходи підсистеми впорядковано як [ω; i]. У сталому режимі без зовнішнього моменту для ω = 100 рад/с потрібні i = 1 А та Vin = 12 В.

## 3. ПІД-регулятор та показники якості

Застосовано ПІД з двома ступенями свободи: пропорційний канал використовує похибку, похідна діє на виміряну швидкість. Це усуває стрибок похідної від ступінчастого завдання. Реалізовано насичення та зворотний розрахунок для захисту інтегратора.

Tf = max(Kd / (20·Kp), 0.001 с); Tt = sqrt(Kd / Ki); N = 1 / Tf.

## 4. Оптимізація та виміряні компроміси

Основний критерій: Jc = IAE / IAEref + λ·Uabs / Uabsref, де IAE = ∫|ωref - ω|dt, Uabs = ∫|Vin|dt. Нормування виконано за базовим регулятором з розміщенням полюсів. Обмеження швидкодії, перерегулювання та перевіреної статичної похибки враховано штрафами.

## 7. Lag та lead на моделі рівнянь

Для C(s) = Kc·(s+z)/(s+p) синтезовано lag з p = 0.01 та lead з p = 20 за розміщенням полюсів; ζ = 0.7. Перевірено додатність параметрів, стійкість номінального замкненого контуру та прогноз статичної похибки. Lag має z > p > 0, lead має p > z > 0.

Для обох компенсаторів використано динамічний стан xc: dxc/dt = -p·xc + e, uraw = Kc·e + Kc·(z-p)·xc. Насичення має ті самі межі ±48 В; корекція стану виконується зворотним розрахунком з Tt = 0.1 с. Без насичення прямі рівняння зіставлено з незалежним lsim; для стрибка моменту перевірено уточнення кроку.

## 8. Simscape та FMU: наступні етапи

Фізична модель має містити DC Motor з Jm та Bm, зовнішню інерцію JL, керовані джерела напруги й протидіючого моменту, датчики струму та швидкості, опорні вузли й Solver Configuration. Параметри повинні збігатися з моделлю рівнянь. Блок передавальної функції не може замінювати фізичну Simscape-мережу.

Підготовлені lag та lead потрібно перенести в замкнений контур фізичної моделі й порівняти з ПІД за тими самими сценаріями та обмеженнями. Потрібно виміряти похибку між фізичною та референсною реалізаціями, а не лише порівняти вигляд графіків.

Потрібно експортувати справжні автономні FMU з MATLAB, перевірити FMI-метадані, іменовані входи/виходи, контрольні суми та виконуваний Windows-бінарний файл. FMPy повинен запускати FMU у незалежному Python-процесі без активного MATLAB, включно зі сценарієм моменту при t = 1 с.
