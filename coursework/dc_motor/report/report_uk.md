## 1. Постановка задачі та математична модель

ДПС приводить жорстко з'єднане інерційне навантаження. Потрібно досягти заданої швидкості протягом 2 с, зменшити похибку та керуючий вплив, зіставити різні реалізації моделі й перевірити компенсацію моменту навантаження.

{{table:parameters}}

Сумарний момент інерції J = Jm + JL = 0.03 кг·м². Навантаження додає лише інерцію; додаткове тертя не задано. Додатний момент TL протидіє додатному обертанню. Початкові умови задаються окремо для кожного сценарію.

La·di/dt = Vin - Ra·i - Ke·ω

J·dω/dt = Kt·i - Bm·ω - TL

За нульових початкових умов та TL = 0:

G(s) = ω(s)/Vin(s) = 0.1 / (0.015·s² + 0.0605·s + 0.012)

Gd(s) = ω(s)/TL(s) = -(0.5·s + 2) / (0.015·s² + 0.0605·s + 0.012)

Вектор станів x = [i; ω]. A = [-4, -0.2; 10/3, -1/30], Bu = [2; 0], Bd = [0; -100/3]. Виходи підсистеми впорядковано як [ω; i]. У сталому режимі без зовнішнього моменту для ω = 100 рад/с потрібні i = 1 А та Vin = 12 В.

## 3. ПІД-регулятор та показники якості

Застосовано ПІД з двома ступенями свободи: пропорційний канал використовує похибку, похідна діє на виміряну швидкість. Це усуває стрибок похідної від ступінчастого завдання. Реалізовано насичення та зворотний розрахунок для захисту інтегратора.

Tf = max(Kd / (20·Kp), 0.001 с); Tt = sqrt(Kd / Ki); N = 1 / Tf.

## 4. Оптимізація та виміряні компроміси

Основний критерій: Jc = IAE / IAEref + λ·Uabs / Uabsref, де IAE = ∫|ωref - ω|dt, Uabs = ∫|Vin|dt. Нормування виконано за базовим регулятором з розміщенням полюсів. Обмеження швидкодії, перерегулювання та перевіреної статичної похибки враховано штрафами.

## 7. Lag та lead на моделі рівнянь

Для C(s) = Kc·(s+z)/(s+p) синтезовано lag з p = 0.01 та lead з p = 20 за розміщенням полюсів; ζ = 0.7. Перевірено додатність параметрів, стійкість номінального замкненого контуру та прогноз статичної похибки. Lag має z > p > 0, lead має p > z > 0.

Для обох компенсаторів використано динамічний стан xc: dxc/dt = -p·xc + e, uraw = Kc·e + Kc·(z-p)·xc. Насичення має ті самі межі ±48 В; корекція стану виконується зворотним розрахунком з Tt = 0.1 с. Без насичення прямі рівняння зіставлено з незалежним lsim; для стрибка моменту перевірено уточнення кроку.

## 8. Фізична модель Simscape та три реалізації

Реалізовано DC Motor з внутрішніми Jm та Bm, окрему інерцію JL, керовані джерела напруги й протидіючого моменту, датчики струму та швидкості, опорні вузли й Solver Configuration. Використано реальні бібліотеки встановленого R2026a. Усередині Motor Model Subsystem збережено контракт Vin/TL → ω/i.

Одиниці параметрів та конвертерів задано явно: Ом, Гн, Н·м/А, кг·м², Н·м·с/рад, В, А та рад/с. Додаткового демпфера немає, щоб не подвоїти Bm. Момент TL проходить через коефіцієнт -1 та протидіє обертанню. Застосовано ode23t, RelTol = 1e-8, AbsTol = 1e-10, MaxStep = 0.001 с.

## 10. FMU: обмін із Python у межах пробної ліцензії

Автономний експорт потребував відсутньої ліцензії Simulink FMU Builder. За вказівкою користувача застосовано офіційний експорт tool-coupling, доступний у Simulink. Це справжні FMU MATLAB формату FMI 2.0 Co-Simulation; FMPy викликає їхній Windows DLL, який виконує модель у локальному ліцензованому MATLAB/Simulink R2026a. Файли не є автономними та не працюють лише з MATLAB Runtime.

Входи двигуна: Vin, TL; виходи: omega, i. Входи замкненого контуру: omega_ref, TL; виходи: omega, i, Vin. Параметри й остаточні коефіцієнти збережено у SLX, початкові стани нульові. Метадані, одиниці, причинність, CRC та SHA256 перевіряються перед виконанням.

## 10.1. Умови виконання FMU та обмеження

Експорт: Simulink.fmuexport.ExportSimulinkProjectToFMU. Додаткова ліцензія FMU Builder та компілятор не потрібні. Потрібні локальні MATLAB і Simulink тієї самої версії, що й експортер. Python запускає окрему службову сесію через офіційний fmu_matlab_setup.exe, керує FMI-входами та після порівняння закриває лише власну сесію. Ручні дії в інтерфейсі не потрібні.

Вхідні сигнали утримуються сталими між точками обміну; момент 0.05 Н·м змінюється точно при t = 1 с. Фіксований локальний крок ode4: 0.00001 с; крок обміну досліджено при 0.001 та 0.0005 с. Час і траєкторії не зсуваються для приховування затримки. Кожен сценарій використовує новий FMI-екземпляр. Сценарій ненульового початкового стану перевірено окремими MATLAB/Python моделями; він не входить до інтерфейсу цих двох FMU.

Оригінальне завдання вимагає експорту FMU та порівняння з Python. Обраний за погодженням користувача спосіб виконує ці дії, але змінює початково заплановану автономну переносимість. На іншому комп'ютері без MATLAB/Simulink запуск неможливий; після завершення пробної ліцензії потрібна чинна ліцензія цих продуктів.
